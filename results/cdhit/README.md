# results/cdhit/

CD-HIT clustering output at 80% sequence identity. **Run via the command line**; `run_pipeline.py --list` prints the exact commands. Runs on the deduplicated, hypothetical-protein-filtered sets, and its output is what gets class-balanced (1:2) and merged for GraphPart.

## Files

- `positive_cdhit80.fasta` / `.clstr` — clustered positive sequences and cluster assignments. 1,117 input → 593 output.
- `negative_cdhit80.fasta` / `.clstr` — clustered negative sequences and cluster assignments. 1,854 input → 1,237 output. Class balancing later samples 1,186 of these.

Clustering removed a larger share of the positive set (47%) than of the negative set (33%), consistent with the greater redundancy of the domain-retrieved positives.

## Command used

Run separately on the deduplicated negative and positive sets:

```bash
cd-hit \
  -i data/negative/negative_dedup.faa \
  -o results/cdhit/negative_cdhit80.fasta \
  -c 0.8 \
  -n 5 \
  -d 0 \
  -T 4 \
  -M 0
```

Same command for the positive set, swapping input and output:

```bash
cd-hit \
  -i data/positive/all_DPO_positive_dedup.fasta \
  -o results/cdhit/positive_cdhit80.fasta \
  -c 0.8 \
  -n 5 \
  -d 0 \
  -T 4 \
  -M 0
```

### Flags

- `-i` — input FASTA file
- `-o` — output FASTA file (non-redundant sequences)
- `-c 0.8` — 80% sequence identity clustering threshold
- `-n 5` — word size, the correct value for `-c 0.8`
- `-d 0` — keeps the full header in the `.clstr` file
- `-T 4` — 4 threads
- `-M 0` — no memory limit

## Pipeline position

Both input files are already deduplicated **and** hypothetical-protein-filtered. CD-HIT's output feeds class balancing (`../../data/negative/negative_sampled.fasta`, sampled from `negative_cdhit80.fasta`) and the merge step (`../../data/merged_input.fasta`), ahead of residue normalisation and GraphPart.

Only the `.clstr` files are tracked in git; the clustered FASTA files are regenerated by running the commands above.
