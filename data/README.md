# data/

Raw and processed sequence data, from initial collection through to the canonical split reference.

## Files

- `final_dataset_40.csv` — **canonical reference file**: sequence list, labels, metadata and the train/valid/test assignment from GraphPart at 40% identity. Every downstream stage reads this file as its single source of truth. 1,779 rows (593 positive, 1,186 negative); split sizes 1,515 / 88 / 176.
- `final_dataset_60.csv` — equivalent for the 60% run. Exploratory only, **not used for the final thesis results**.
- `merged_metadata.csv` — product, organism, description and sequence per row, written alongside the merged FASTA.
- `protein_domains.csv` — the seven CDD/Pfam domain accessions used to retrieve the positive set, with descriptions.

## Generated files (gitignored, regenerated by the pipeline)

- `merged_input.fasta` — positive + negative sequences after class balancing, with sequential IDs and `label`/`orig_id` encoded in the header.
- `merged_input_normalized.fasta` — the same file with ambiguous residues (B, Z, J, U, O) mapped to X. This is the canonical sequence source for every downstream branch: GraphPart, embedding extraction and external tool retraining. A single sequence was affected by the mapping; the code X was already present in 45 sequences as deposited.
- `train_sequences_clean.fasta`, `test_sequences_clean.fasta` — per-split FASTA files written by `../src/make_train_fasta.py`, used by the external tool retraining scripts.

## Subfolders

- `positive/` — positive (DPO) sequence collection, by conserved domain
- `negative/` — negative (non-DPO) collection, with the filtering and balancing steps
